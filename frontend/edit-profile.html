I2 — FAIR Vocabularies Configurable
Which controlled vocabularies metadata should reference. The system uses a two-layer check: vocabulary presence, then vocabulary FAIRness level.
What is a vocabulary FAIR level?
Based on Cox et al. (2021) "Ten Simple Rules for Making a Vocabulary FAIR" (PLOS Computational Biology). This second layer checks whether the vocabulary itself is FAIR, not just whether the dataset references it.

Level Requirement Score Cox et al. Rule
None No vocabulary FAIR check — only checks if vocabulary is referenced in metadata — —
Basic Vocabulary URI must resolve via HTTP (vocabulary is online and accessible) ≥ 40% Rule 1
Standard recommended Above + machine-readable format available (RDF, OWL, or SKOS serialisation) ≥ 60% Rules 1–4
Full Above + licence declaration present in the vocabulary ≥ 80% Rules 1–4, 10
Typical usage: Scientific/academic domains → Standard  ·  General use → Basic  ·  Strict community requirements → Full
Pre-verified vocabularies: AGROVOC (full), MeSH (full), ENVO (full), schema.org (full), Dublin Core (full), DCAT (full), SKOS (full), DDI (standard)
Add vocabulary name + keywords to detect in metadata. The system will search for these keywords in metadata fields.
ℹ️ Vocabulary detection uses keyword matching against available metadata fields. If a repository does not expose vocabulary references in their API response, this check may fail even if the dataset uses the correct vocabulary.
Scans metadata for known ontology namespace URIs (schema.org, DCAT, SKOS, Dublin Core, OBO, etc.) instead of keyword matching. Stricter — fails if no registered namespace URI is found.

License field must start with http:// or https:// to pass.
R1.2 — Provenance Configurable
Checks for http://www.w3.org/ns/prov or http://purl.org/pav URIs in the metadata response. Without them the metric is downgraded to partial.
